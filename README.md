## 2026-11-08 通知経路の堅牢化
- **既存の通知判定を維持**：70点、暫定60指数、RR1:1.5、5通貨、指標と週末条件は変更しません。新規通知数や実勝率は未測定です。
- OneSignalの宛先をNetlify環境変数 `ONESIGNAL_SUBSCRIPTION_IDS`（カンマ区切りの購読ID）で指定できるようにしました。設定がない場合は従来の2件を引き続き使います。端末側で購読IDが変わった場合は、**最新のIDを環境変数に設定する必要があります**。アプリIDは任意の `ONESIGNAL_APP_ID` で上書きできます。
- Netlifyログに、APIキーの有無・宛先数・設定値の有効性を出力します（APIキーやIDそのものはログ出力しません）。通知の診断にも含みます。
- OneSignal通信の12秒タイムアウトを追加。HTMLなどJSON以外のエラーでも、失敗理由を監視ログに残します。送信受理と実際の端末到達は異なります。
- 通貨別の画面用スナップショット保存で失敗した場合、他の通貨の処理を巻き込んで停止させないようにしました。保存失敗を `pairErrors` とNetlifyログに出します。
- **Blobs本体の保存失敗時は安全のため通知しません**。実績・重複防止を破壊しないための仕様です。Netlify Blobsが正常動作するかはデプロイ後に確認が必要です。

### 導入・確認手順
1. GitHubのルートへZIP内の `fx-ai-tool-simple` フォルダーの**中身**を反映（フォルダーを二重に作らない）。Netlifyビルド成功を確認。
2. Netlify Environment variablesの `ONESIGNAL_API_KEY` と `TWELVE_DATA_API_KEY` が設定されていることを確認。必要なら `ONESIGNAL_SUBSCRIPTION_IDS` に現在使っている端末の購読IDを設定して再デプロイ。
3. FX市場営業中に Netlify Function logs の `FX push configuration:` 、`FX feed diagnostic:` 、`FX monitor result:` 、`FX pair monitor failed:` を確認。
4. 画面で `notificationReason` / `skipReasons` / `monitoringHealth` を確認。送信受理なのに端末に届かない場合は、端末のOneSignal購読状態・通知許可を確認。
